# Сжатие контекстной памяти языковых моделей

Если история общения длинная, модель может читать её частями и сохранять краткую запись важных фактов. Эта запись называется рабочей памятью. При смене задачи могут понадобиться сведения, которые раньше казались второстепенными и не попали в память.

Проект проверяет, помогает ли дополнительная проверка краткой записи сохранить нужные сведения и оправдывает ли она расходы. Для этого сравниваются Summary с одним запросом на обновление памяти и Reflexive с отбором фактов, сжатием и проверкой. Объём памяти у методов одинаковый.

На изученной выборке Reflexive не показал устойчивого преимущества и стоил дороже. Более сильная модель улучшила оба метода. После смены цели успешный ответ часто сопровождался повторным чтением источников. Это предварительное исследование с небольшими выборками и одним прогоном на сочетание условий.

Проведены две серии через API, программный интерфейс внешнего сервиса языковых моделей. Такие серии названы платными, поскольку расход рассчитывается по обработанным токенам. Всего выполнено 686 прогонов на 48 основных примерах. Один прогон решает одну задачу выбранным способом и может включать много запросов.

На BABILong часть различий связана с формой ответа. Например, `the hallway` не совпадает с эталоном `hallway` по исходному правилу, хотя оба ответа называют коридор. [Дополнительный разбор](docs/reports/analysis/babilong_sensitivity.md) показывает, как удаление начального артикля меняет оценку. Исторические оценки сохранены.

## Что сравнивается

| Метод | Обновление памяти | Вызовы на обновление |
| --- | --- | --- |
| Summary | Старая память и новый фрагмент превращаются в новую память | 1 |
| Reflexive | Модель выбирает факты, сжимает память и проверяет сохранность выбранных фактов | 3 |

Исходный текст остаётся в журнале. Если памяти недостаточно, модель может запросить один поиск с чтением до двух фрагментов. Проверка Reflexive охватывает выбранные факты, поэтому она не гарантирует полноту отбора. Ссылки на источники показывают происхождение записи, но не доказывают её истинность.

Подключены PersonaMem 32k и BABILong qa1/8k. Для смены цели используется собственный набор с поставщиками. На PersonaMem добавлены контроли с полным контекстом и последним окном. Их условия и ограничения разобраны в отчёте.

## Быстрый запуск

Нужен Python 3.11+. Из корня проекта в macOS или Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev,bench]"
python -m context_memory smoke
```

Smoke по умолчанию использует заданные mock-ответы. Это проверка программы без вызова модели. Для PowerShell окружение активируется командой `.venv\Scripts\Activate.ps1`. Вместо `python3` можно использовать `py -3.11`.

Готовый отчёт можно пересобрать без установки зависимостей модели и без сетевых запросов:

```bash
python3 tools/build_research_report.py
```

## Что находится в репозитории

Пакет `context_memory/` содержит контроллер, клиентов моделей, оценку и команды запуска. `tests/` проверяет протокол и обработку ошибок. В `examples/` сохранены результаты и часть полных журналов; `docs/` содержит описание исследования.

Полные исходные датасеты и большинство платных журналов находятся вне Git. Из клона можно проверить сводные ответы и расходы, но нельзя восстановить все отсутствующие промежуточные стадии. Настройки и промпты исходных экспериментов при редактуре документации не менялись.
