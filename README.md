# Сжатие контекстной памяти языковых моделей

Проект сравнивает два способа сохранять сведения из длинной истории: одношаговое обновление памяти Summary и трёхстадийное Reflexive.

Исследовательский вопрос: помогает ли трёхстадийное обновление точнее отвечать после смены цели при одинаковом размере памяти и оправдывает ли результат дополнительные расходы? Сравниваются два полных процесса обновления; отдельный эффект проверяющей стадии не установлен. Для смены цели показаны три результата: первая задача, новая задача до поиска и итог после повторного чтения.

На опубликованной выборке Reflexive не показал устойчивого преимущества и стоил дороже. Более сильная модель улучшила оба метода; после смены цели часто помогало повторное чтение источников. Две платные серии включают 686 прогонов на 48 основных примерах. Это пилотное исследование с одним прогоном на комбинацию условий.

На BABILong часть различий связана с формой ответа: `the hallway` не совпадает с эталоном `hallway` по исходной строгой метрике. [Отдельный анализ чувствительности](docs/research/babilong_sensitivity.md) показывает результаты после удаления начального артикля и категории ответов. Исторические оценки сохранены; неоднозначные фразы автоматически не переоцениваются.

**Результаты:** [исследовательский отчёт HTML](docs/research/report.html) · [краткий PDF](docs/research/report.summary.pdf) · [PDF со всеми ответами](docs/research/report.pdf) · [все 686 ответов CSV](docs/research/all_answers.csv).

## Что сравнивается

| Метод | Обновление памяти | Вызовы на обновление |
| --- | --- | --- |
| Summary | Старая память и новый фрагмент превращаются в новую память | 1 |
| Reflexive | Модель выбирает факты, сжимает память и проверяет сохранность выбранных фактов | 3 |

Исходный текст остаётся в журнале. Если памяти недостаточно, модель может запросить один поиск с чтением до двух фрагментов. Проверка Reflexive охватывает выбранные факты; она не гарантирует полноту отбора. Ссылки на источники показывают происхождение записи, но не доказывают её истинность.

Подключены PersonaMem 32k и BABILong qa1/8k. Для смены цели используется собственный набор с поставщиками. На PersonaMem добавлены контроли с полным контекстом и последним окном. Их условия и ограничения разобраны в отчёте.

## Быстрый запуск

Нужен Python 3.11+. Из корня проекта в macOS или Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev,bench]"
python -m context_memory smoke
```

Smoke по умолчанию использует заданные mock-ответы. Это проверка программы без вызова модели. Для PowerShell окружение активируется командой `.venv\Scripts\Activate.ps1`; вместо `python3` можно использовать `py -3.11`.

Готовый отчёт можно пересобрать без установки зависимостей модели и без сетевых запросов:

```bash
python3 tools/build_research_report.py
```

## Что находится в репозитории

Пакет `context_memory/` содержит контроллер, клиентов моделей, оценку и команды запуска. `tests/` проверяет протокол и обработку ошибок. В `examples/` сохранены результаты и часть полных журналов; `docs/` содержит описание исследования.

Полные исходные датасеты и большинство платных журналов находятся вне Git. Из клона можно проверить сводные ответы и расходы, но нельзя восстановить все отсутствующие промежуточные стадии. Настройки и промпты исходных экспериментов при редактуре документации не менялись.
