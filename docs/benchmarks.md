# Данные и методика оценки

Исследование проверяет два разных навыка: сохранение фактов при последовательном чтении и использование прежней истории после изменения задачи. Для них выбраны разные наборы; их точности не объединяются в общий рейтинг.

## Использованные наборы

| Набор | Что проверяет | Выборка в платных сериях |
| --- | --- | --- |
| PersonaMem 32k | Факты о пользователе, предпочтения и причины их изменений | 16 персон, по одному вопросу |
| BABILong qa1/8k | Поиск факта среди длинного отвлекающего текста | 20 примеров, строки 5–24 |
| Собственная смена цели | Исправление факта, затем новая цель | 12 сценариев с поставщиками |

Для PersonaMem вопрос раскрывается после истории. Для BABILong он известен до чтения. В собственном сценарии сначала выбирается дешёвый поставщик с доставкой до пяти дней, затем нужен код договора самого быстрого. Эти условия нельзя считать одной и той же задачей на память.

## Адаптация PersonaMem

Источник — [bowen-upenn/PersonaMem](https://huggingface.co/datasets/bowen-upenn/PersonaMem), файлы `questions_32k.csv` и `shared_contexts_32k.jsonl`. Используется префикс истории до `end_index_in_shared_context`. Роли и текст сообщений сохраняются, включая исходный system-профиль; для нашего агента это данные, а не инструкция.

Первые 20% persona_id в лексикографическом порядке отведены под debug, остальные — под eval. Это разделение проекта, не официальный split авторов. В сохранённом экспорте 118 debug-вопросов и 471 eval-вопрос. В платной серии выбрано по одному вопросу для 16 eval-персон с фиксированным seed 20261101; отбор не читает эталоны.

Модель возвращает одну букву a–d. Допускаются регистр, скобки и конечная точка. Объяснение вместо буквы или несколько вариантов не засчитываются. Это локальная строгая метрика проекта.

## Адаптация BABILong

Источник — [RMT-team/babilong-1k-samples](https://huggingface.co/datasets/RMT-team/babilong-1k-samples), один файл `8k/qa1-00000-of-00001.parquet`. Строки 0–4 используются для отладки, 5–24 — для оценки. Точное совпадение считается после приведения к нижнему регистру, удаления пробелов по краям и одной конечной точки.

Оба адаптера фиксируют ревизию и хеши файлов. Входы и эталоны экспортируются отдельно. С `--no-score` генерация не открывает файл эталонов; отдельный оценщик работает без модели. Все запрошенные прогоны, включая ошибки, остаются в знаменателе точности.

## Сравнение методов

Summary и Reflexive получают одинаковую память 512 токенов и одни и те же примеры. Число вызовов и расходы различаются и измеряются отдельно. Для PersonaMem добавлены полный контекст с окном 65536 и суффикс истории до 4096 токенов. Это контроли с другими условиями доступа к данным.

Приведены интервалы Wilson для точности и точный парный McNemar для различий. Bootstrap описывает парную разницу на наблюдаемой выборке. Сравнения разведочные, без поправки на множественные проверки. Один прогон на комбинацию не позволяет оценить вариативность повторных запусков.

## Наборы для дальнейшей работы

[AgentChangeBench](https://github.com/Maniktherana/AgentChangeBench) проверяет смену цели в среде с инструментами. Для подключения нужен адаптер к tau2; обычные вопросы по извлечённому тексту не воспроизводят этот протокол. Адаптер пока отсутствует.

[MemoryAgentBench](https://github.com/HUST-AI-HYZ/MemoryAgentBench) и [LongMemEval](https://github.com/xiaowu0162/LongMemEval) остаются кандидатами для более широких проверок. Свободные ответы потребуют отдельной схемы независимой оценки. В текущих сериях эти наборы не использовались.

Обзор источников первоначально подготовлен 23 октября 2026 года. Материалы выступлений конференции не использовались как доказательство: расшифровка присланной записи не была получена.
