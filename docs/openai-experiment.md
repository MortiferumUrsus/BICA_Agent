# Первый эксперимент OpenAI

Протокол от 1 ноября 2026. Бюджет пользователя — $28; программа ограничена $26. Отладка, повторные попытки и основной эксперимент используют один журнал расходов.

Эксперимент завершён: **512/512 прогонов, $9.38 с отладкой**. [Результаты и графики](../examples/openai-20261101/README.md).

## Модели

| Версия | Размышления | Вход / cached / выход, USD за 1M токенов |
|---|---|---|
| `gpt-4.1-mini-2025-04-14` | без reasoning | 0.40 / 0.10 / 1.60 |
| `gpt-5.4-nano-2026-03-17` | `low`, отдельно `none` | 0.20 / 0.02 / 1.25 |
| `gpt-5.4-mini-2026-03-17` | `low` | 0.75 / 0.075 / 4.50 |

Тарифы проверены по [официальной странице](https://developers.openai.com/api/docs/pricing). Используется стандартный тариф без инструментов. Выход включает скрытые reasoning tokens. Версии зафиксированы для сравнения, их доступность проверена реальными запросами; это не подбор текущего SOTA.

`low` выбран как недорогой режим рассуждения; сравнение nano с `none` отдельно проверяет его вклад. [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) и [nano](https://developers.openai.com/api/docs/models/gpt-5.4-nano) поддерживают оба режима. GPT-4.1 mini не имеет отдельного шага reasoning.

## Выборка и методы

- PersonaMem: 16 разных eval-персон, по одному вопросу на каждую. Детерминированный выбор с seed 20261101, типы вопросов чередуются. Эталоны при выборе не читаются. Вопрос и варианты раскрываются после чтения истории.
- BABILong 8k qa1: все 20 ранее выделенных eval-примеров. Вопрос известен до чтения.
- Наш диагностический набор: 12 сценариев. Сначала выбирается дешёвый поставщик с ограничением по сроку, затем цель меняется на поиск кода договора самого быстрого поставщика. Есть исправление цены и отвлекающий текст. Это не реализация AgentChangeBench.

На каждом примере сравниваются `summary` и `reflexive`. На PersonaMem дополнительно выполняются `full_context` (вся история, окно 65536) и `last_window` (суффикс не длиннее 4096 токенов). Полный контекст — контроль с большим доступным контекстом, а не равный по ограничениям метод сжатия. Всего 512 назначенных прогонов, три разные модели и четыре настройки model/reasoning.

Основные ограничения: память 512, состояние 512, окно с резервом ответа 8192, фрагмент 2048 токенов cl100k_base. Лимит API-выхода — 2048 нативных токенов, включая reasoning. До двух дополнительных попыток при нарушении схемы или размера; не более одного поиска с чтением двух фрагментов на вопрос. У всех методов сжатия одинаковые настройки. Разница стоимости из-за трёх стадий reflexive сохраняется в результатах.

Промпты проверялись на debug-персоне и коротком сценарии. До основного запуска сохранены ID выборки, порядок заданий, хеши промптов и реализации. После начала eval промпты не меняются. Имена выходных файлов фиксированы: повторный запуск пропускает готовые задания и отказывается перезаписывать прерванное задание.

## Запуск

Установка и загрузка данных:

```powershell
python -m pip install -e ".[dev,bench,plots]"
python -m context_memory fetch-benchmark --dataset personamem
python -m context_memory fetch-benchmark --dataset babilong
python -m pytest -q
```

Ключ задаётся через `OPENAI_API_KEY` либо `OPENAI_API_KEY_FILE`. Во втором случае файл содержит только ключ. Не помещайте значение ключа в команды, отчёты или Git. Сам ключ не сохраняется клиентом в результатах.

Пример отдельного платного проверочного запуска:

```powershell
python -m context_memory smoke --provider openai-api --live --model gpt-5.4-nano-2026-03-17 --reasoning-effort low --budget-usd 26 --ledger runs/openai-first-20261101/budget.sqlite3 --window-ref-tokens 8192 --max-output-tokens 2048 --state-ref-tokens 512 --format-retries 2 --timeout-s 120 --out runs/openai-smoke
```

Для GPT-4.1 mini укажите `--reasoning-effort none`: параметр reasoning в API не передаётся. Провайдер `openai` по-прежнему обозначает локальный совместимый сервер; `openai-api` — платный API OpenAI.

Подготовка новой серии и запуск:

```powershell
python -m context_memory.study debug --workers 8
python -m context_memory.study prepare
python -m context_memory.study run --workers 8
python -m context_memory.study score
python tools/audit_study.py runs/openai-first-20261101
python tools/plot_study.py runs/openai-first-20261101/analysis/results.json
```

По умолчанию используются `runs/openai-first-20261101/` и общий `budget.sqlite3`. Не удаляйте журнал расходов и не создавайте новый для продолжения того же бюджета. Для новой оплачиваемой серии нужен отдельный бюджет и каталог `--out`; текущий протокол рассчитан на $26. Подготовка не перезаписывает существующий протокол. Параллельно выполняются независимые задания, стадии внутри одного агента всегда последовательны.

В `analysis/` появляются `report.md`, `results.json`, `predictions.csv`. `tasks/` хранит запросы, ответы, memory snapshots, источники и трассы. Эти объёмные журналы остаются локально. Небольшая копия протокола и результатов может храниться в `examples/`.

## Расходы и оценка

Перед каждым запросом резервируется консервативная сумма: верхняя оценка входа по UTF-8-байтам с запасом плюс полный лимит выхода по проверенному тарифу. SQLite-транзакция не позволяет параллельным заданиям потратить один остаток дважды. После ответа резерв заменяется стоимостью usage; при неизвестном исходе остаётся полный резерв. После сбоя или перезапуска эти суммы сохраняются. Это бюджет данного эксперимента, он не учитывает чужие запросы к тому же аккаунту.

Оценщик запускается отдельно и не вызывает модель. PersonaMem проверяется по метке варианта, BABILong и диагностические сценарии — по точному ответу после нормализации регистра и крайних пробелов. В знаменателе остаются все назначенные задания, включая ошибки. Для смены цели отдельно проверяются первый и второй ответы.

Основное сравнение — парная разница точности `reflexive − summary` на одной выборке. Отчёт показывает также стоимость, число вызовов, результат до/после поиска, интервалы Wilson и парный bootstrap. Одна реализация на комбинацию не оценивает вариативность повторных запусков. Небольшая выборка и несколько сравнений требуют осторожности при заявлении преимущества метода.

При дальнейших запусках через OpenRouter нужно сохранить эту выборку, настройки и правила оценки. Добавление китайских моделей — отдельная серия, не включённая в текущие расходы OpenAI.
