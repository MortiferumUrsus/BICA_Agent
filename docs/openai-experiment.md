# Первый эксперимент OpenAI

Этот протокол от 1 ноября 2026 года описывает первый эксперимент с моделями OpenAI. Хотелось проверить, как способы работы с памятью проявят себя на разных задачах и во сколько обойдётся такое сравнение. Из выделенных пользователем $28 программный лимит составил $26. Расходы на отладку, повторные попытки и основной запуск учитывались в одном журнале.

Эксперимент завершён. Выполнены **512/512 прогонов**, общие расходы с учётом отладки составили **$9.38**. Подробные [результаты и графики](../examples/openai-20261101/README.md) вынесены в отдельный отчёт.

## Модели

| Версия | Размышления | Вход / cached / выход, USD за 1M токенов |
|---|---|---|
| `gpt-4.1-mini-2025-04-14` | без reasoning | 0.40 / 0.10 / 1.60 |
| `gpt-5.4-nano-2026-03-17` | `low`, отдельно `none` | 0.20 / 0.02 / 1.25 |
| `gpt-5.4-mini-2026-03-17` | `low` | 0.75 / 0.075 / 4.50 |

Тарифы для эксперимента проверены по [официальной странице](https://developers.openai.com/api/docs/pricing). В расчётах используется стандартная стоимость запросов без инструментов, а в выходные токены входят и скрытые токены рассуждения, reasoning tokens. Версии моделей зафиксированы, доступность каждой проверена реальными запросами. Здесь интересовало сравнение в заданных условиях, а не поиск самой сильной модели на текущий момент, или SOTA.

Режим `low` выбран как недорогой способ включить рассуждение. При этом хотелось отдельно проверить, что даёт сам этот режим, поэтому для nano добавлен запуск с `none`. И [GPT-5.4 mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini), и [nano](https://developers.openai.com/api/docs/models/gpt-5.4-nano) поддерживают оба варианта. У GPT-4.1 mini отдельного шага reasoning нет.

## Выборка и методы

Для проверки взяты три набора с разными условиями работы с историей. В PersonaMem вошли 16 разных eval-персон, по одному вопросу на каждую. Выбор детерминированный, с seed 20261101 и чередованием типов вопросов. Эталонные ответы при отборе не читаются. Сам вопрос и варианты ответа становятся доступны только после чтения истории.

В BABILong 8k qa1 использованы все 20 ранее выделенных eval-примеров. Здесь вопрос известен заранее, ещё до чтения. Это существенное отличие от PersonaMem, которое нужно учитывать при сопоставлении результатов.

Ещё 12 сценариев составляют наш диагностический набор. В них сначала требуется выбрать дешёвого поставщика с учётом ограничения по сроку, а затем задача меняется. Теперь нужно найти код договора самого быстрого поставщика. В историю добавлены исправление цены и отвлекающий текст, чтобы проверить работу памяти при смене цели. Этот набор не является реализацией AgentChangeBench.

На каждом примере сравниваются `summary` и `reflexive`. Для PersonaMem добавлены ещё два варианта. В `full_context` доступна вся история при окне 65536, а `last_window` получает только её суффикс длиной не более 4096 токенов. Полный контекст служит контрольным вариантом с большим объёмом доступной информации. Приравнивать его к методам сжатия по ограничениям было бы некорректно. Всего назначено 512 прогонов для трёх моделей и четырёх сочетаний model/reasoning.

Для методов сжатия установлены одинаковые ограничения. На память и состояние отводится по 512 токенов cl100k_base, на окно с резервом ответа 8192, на отдельный фрагмент 2048. Лимит выхода API составляет 2048 нативных токенов и включает reasoning. Если ответ нарушает схему или допустимый размер, разрешены до двух дополнительных попыток. На один вопрос допускается не более одного поиска с чтением двух фрагментов. При этом три стадии `reflexive` влияют на расходы, и эта разница стоимости сохраняется в результатах.

Промпты предварительно проверялись на debug-персоне и коротком сценарии. До основного запуска сохранены ID выборки, порядок заданий, хеши промптов и реализации. После начала eval промпты не меняются. Так сохраняются единые условия для всей серии. Имена выходных файлов тоже фиксированы. При повторном запуске программа пропускает готовые задания и отказывается перезаписывать прерванное задание.

## Запуск

Сначала нужно установить зависимости, загрузить данные и выполнить тесты.

```powershell
python -m pip install -e ".[dev,bench,plots]"
python -m context_memory fetch-benchmark --dataset personamem
python -m context_memory fetch-benchmark --dataset babilong
python -m pytest -q
```

Ключ задаётся через `OPENAI_API_KEY` либо `OPENAI_API_KEY_FILE`. Если выбран второй способ, файл должен содержать только ключ. Его значение не следует помещать в команды, отчёты или Git. Клиент не сохраняет сам ключ в результатах.

Перед основной серией можно выполнить отдельный платный проверочный запуск.

```powershell
python -m context_memory smoke --provider openai-api --live --model gpt-5.4-nano-2026-03-17 --reasoning-effort low --budget-usd 26 --ledger runs/openai-first-20261101/budget.sqlite3 --window-ref-tokens 8192 --max-output-tokens 2048 --state-ref-tokens 512 --format-retries 2 --timeout-s 120 --out runs/openai-smoke
```

Для GPT-4.1 mini нужно указать `--reasoning-effort none`. В этом случае параметр reasoning в API не передаётся. В обозначениях провайдеров сохранено прежнее различие. `openai` относится к локальному совместимому серверу, а `openai-api` обращается к платному API OpenAI.

Новая серия проходит подготовку, запуск и оценку в следующем порядке.

```powershell
python -m context_memory.study debug --workers 8
python -m context_memory.study prepare
python -m context_memory.study run --workers 8
python -m context_memory.study score
python tools/audit_study.py runs/openai-first-20261101
python tools/plot_study.py runs/openai-first-20261101/analysis/results.json
```

По умолчанию результаты сохраняются в `runs/openai-first-20261101/`, а расходы учитываются в общем `budget.sqlite3`. При продолжении работы в рамках того же бюджета этот журнал нельзя удалять или заменять новым. Для новой оплачиваемой серии нужны отдельный бюджет и каталог `--out`, поскольку текущий протокол рассчитан на $26. Подготовка не перезаписывает уже существующий протокол. Независимые задания могут выполняться параллельно, но стадии внутри одного агента всегда идут последовательно.

После обработки в `analysis/` появляются `report.md`, `results.json` и `predictions.csv`. В `tasks/` сохраняются запросы, ответы, снимки памяти (memory snapshots), источники и трассы выполнения. Эти журналы занимают много места и остаются локально. В `examples/` можно хранить небольшую копию протокола и результатов.

## Расходы и оценка

Перед каждым запросом программа резервирует сумму с запасом. Для этого верхняя оценка входа по UTF-8-байтам складывается со стоимостью полного лимита выхода по проверенному тарифу. Резервирование выполняется в SQLite-транзакции, поэтому параллельные задания не могут дважды потратить один и тот же остаток. Когда ответ получен, резерв заменяется фактической стоимостью по данным usage. Если исход запроса неизвестен, полный резерв остаётся в журнале. Эти суммы сохраняются и после сбоя или перезапуска. Учёт охватывает только данный эксперимент, поэтому чужие запросы к тому же аккаунту в него не входят.

Оценка выполняется отдельно, без новых вызовов модели. В PersonaMem проверяется метка выбранного варианта. Для BABILong и диагностических сценариев требуется точное совпадение ответа после приведения регистра и удаления пробелов по краям. При расчёте точности в знаменателе остаются все назначенные задания, в том числе завершившиеся ошибкой. В сценариях со сменой цели первый и второй ответы оцениваются отдельно.

Главный интерес представляет парная разница точности `reflexive − summary` на одной и той же выборке. Вместе с ней в отчёте приведены стоимость, число вызовов, результаты до и после поиска, интервалы Wilson и парный bootstrap. Однако для каждого сочетания условий выполнен только один запуск, поэтому вариативность при повторении эксперимента здесь не оценена. Выборка небольшая, сравнений несколько. Это ограничивает уверенность, с которой можно говорить о преимуществе того или иного метода.

При продолжении эксперимента через OpenRouter нужно сохранить ту же выборку, настройки и правила оценки, чтобы результаты оставались сопоставимыми. Добавление китайских моделей потребует отдельной серии. Её расходы не входят в текущие затраты на OpenAI.
