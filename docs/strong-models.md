# Продолжение на GPT-6

[Результаты завершённой серии](../examples/openai-strong-20261101/README.md): 174 дополнительных прогона, $18.49891720; общий расход обеих серий $27.87631429 из $28. Ошибок исполнения и неизвестных расходов нет.

После первой серии пользователь разрешил потратить остаток исходных $28 на более сильные модели. Ранее израсходованные $9.37739709 сохранены в общем журнале. Лимит увеличен с $26 до $28 явной операцией с записью причины; новый независимый бюджет не создавался.

## Модели и стоимость

| Модель | Reasoning | Вход | Cached input | Cache write 30m | Выход |
|---|---|---:|---:|---:|---:|
| GPT-6.1 Sol | low | $2.00 | $0.10 | $2.50 | $10.00 |
| GPT-6 Astra | low | $10.00 | $1.00 | $12.50 | $50.00 |

Цены за миллион токенов, Standard, проверены 1 ноября 2026: [Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Astra](https://developers.openai.com/api/docs/models/gpt-6-astra). В документации Sol описан как модель для сложной работы с качеством, близким к Astra, при меньшей цене. Astra — более дорогая старшая модель. Фактическое преимущество в нашем фреймворке проверяется экспериментом, а не предполагается из названия.

Запись в кеш оплачивается по полной ставке 1.25× входа, не как двойная плата за те же токены. Учитываются `prompt_tokens_details.cache_write_tokens`; default TTL 30m. Подробности — в [официальной документации](https://developers.openai.com/api/docs/guides/prompt-caching). Выходной лимит включает reasoning tokens.

У обеих моделей оставлен `low`, чтобы отделить смену модели от изменения режима размышлений. В API доступны недатированные ID; они и фактически возвращённый ID записываются в трассы. Точная фиксация весов на будущие даты этим не гарантируется.

## Протокол

Sol проходит все прежние 48 примеров: 16 PersonaMem, 20 BABILong, 12 диагностических смен цели. На каждом выполняются summary/reflexive, а на PersonaMem ещё full_context/last_window — всего 128 прогонов.

Промпты, исходные тексты, момент раскрытия вопроса и ограничения совпадают с первой серией: память 512, состояние 512, окно 8192, блок 2048, выход 2048 токенов. Полный контекст использует окно 65536. После просмотра результатов первой серии промпты не менялись. Новый клиент отличается поддержкой GPT-6 и корректным учётом кеша.

Astra получает оставшийся бюджет после завершения Sol. Очередь определена заранее: сначала 12 смен цели, затем BABILong, затем PersonaMem. Перед допуском пары summary/reflexive расход оценивается по токенам Sol на том же примере, пересчитанным по ставкам Astra: 1.5× оценка плюс $0.15. Общий лимит дополнительно проверяется перед каждым отдельным запросом.

Если на следующую пару бюджета не хватает, проверяются одношаговые контроли Astra на PersonaMem: сначала full_context, затем last_window, в порядке ID. Каждый допускается только при наличии суммы на полный консервативный резерв. Непоместившиеся задания не назначаются и фиксируются в `admissions.json`. Правильность ответов не влияет на выбор задач.

До оценки новых ответов добавлен последний бюджетный этап: если после Astra остаётся сумма, недостаточная для её следующего запроса, выполняются более дешёвые одношаговые контроли Sol с reasoning `medium`, в том же порядке. Это отдельная малая проверка режима ответа, а не повтор всего метода сжатия с medium. Её ограничения и результаты не смешиваются с основной серией low.

Размер выборки Astra может отличаться от Sol. Сравнение моделей рассчитывается на пересечении ID, отдельно для каждого метода и набора. Эталоны читает только офлайн-оценщик, LLM-судьи нет. Все назначенные задания остаются в знаменателе, включая ошибки. Это продолжение на тех же данных, а не новый независимый holdout.

## Команды текущего эксперимента

Нужны существующий журнал первой серии, её сохранённые inputs/protocol и ключ в `OPENAI_API_KEY` или `OPENAI_API_KEY_FILE`. Не удаляйте SQLite-журнал: он хранит общий расход обеих серий.

```powershell
python -m context_memory.strong_study prepare
python -m context_memory.strong_study sol --workers 8
python -m context_memory.strong_study astra
python -m context_memory.strong_study controls
python -m context_memory.strong_study medium-controls
python -m context_memory.strong_report runs/openai-strong-20261101
python tools/audit_study.py runs/openai-strong-20261101
python tools/plot_strong_study.py runs/openai-strong-20261101/analysis/results.json
```

Существующий протокол не перезаписывается. Готовые задания пропускаются; прерванный отдельный прогон требует проверки перед повтором. Сохранённые отчёты первой серии используют её исторический снимок расходов и не включают последующие списания.
