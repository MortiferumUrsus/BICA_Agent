# Подготовка и запуск тестирования

Версия 0.2. Все команды выполняются из корня проекта после установки `pip install -e ".[dev,bench]"`. В PowerShell без активированного окружения замените `python` на `.venv\Scripts\python.exe`.

Подготовка от 23 октября: [167 тестов и аудит](../examples/preparation-20261023/readiness.json), [план PersonaMem](../examples/preparation-20261023/personamem-plan.json). Новый прогон реальной модели не выполнен: автоматическая проверка команд заблокировала фоновый запуск Ollama. Ниже приведены команды для ручного запуска.

## Проверка программы без модели

```bash
python -m pytest -q
python -m context_memory smoke --out runs/smoke-mock
```

Mock не решает произвольные задачи. Он проверяет контроллер, поиск и сохранение результатов. Тесты блокируют сетевые вызовы и проверяют отсутствие эталонов в запросах.

## Проверка выбранной модели

Для локальной проверки подходит небольшой instruct-вариант Qwen. Например, [Qwen3 4B Instruct 2507](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), доступный в [Ollama](https://ollama.com/library/qwen3:4b-instruct-2507-q4_K_M). Это конкретная конфигурация для запуска, а не утверждение о текущем SOTA.

```bash
ollama serve
```

В другом терминале:

```bash
ollama pull qwen3:4b-instruct-2507-q4_K_M
python -m context_memory doctor --provider ollama --model qwen3:4b-instruct-2507-q4_K_M
python -m context_memory smoke --provider ollama --model qwen3:4b-instruct-2507-q4_K_M --format-retries 1 --timeout-s 180 --out runs/smoke-qwen
```

`doctor` проверяет доступность без генерации. `smoke` выполняет короткое обновление факта в обоих режимах и сверяет ответ кодом. При неверном ответе или ошибке возвращается ненулевой код. Сначала исправляются проблемы этого прогона, затем запускается длинный набор. Для холодной загрузки модели увеличен таймаут; повторный вызов после сетевого таймаута может повторно выполнить уже начатую работу на сервере.

Если модель не помещается в VRAM, нужно выбрать меньшую модель или использовать сервер. Программа не выбирает замену автоматически. По умолчанию отключены повторные попытки исправления формата; `--format-retries 1` разрешает один дополнительный вызов из того же состояния. Его расход входит в общий учёт. Значения фактов и неизвестные ID автоматически не исправляются.

## Видеокарты в кабинете

Поддержан OpenAI-совместимый локальный сервер, например [vLLM](https://docs.vllm.ai/en/latest/serving/online_serving/). На Linux-сервере с подходящей GPU и установленным vLLM:

```bash
vllm serve Qwen/Qwen3-4B-Instruct-2507 --host 127.0.0.1 --port 8000 --max-model-len 8192
```

Проброс порта с рабочего компьютера:

```bash
ssh -N -L 8000:127.0.0.1:8000 user@gpu-host
```

Затем:

```bash
python -m context_memory doctor --provider openai --model Qwen/Qwen3-4B-Instruct-2507
python -m context_memory smoke --provider openai --model Qwen/Qwen3-4B-Instruct-2507 --timeout-s 180 --format-retries 1 --out runs/smoke-server
```

Здесь `openai` обозначает формат API локального сервера. Облачный OpenAI не вызывается. URL задаётся через `--local-url`, по умолчанию `http://127.0.0.1:8000/v1`. Поддерживается loopback-адрес, в том числе при SSH-пробросе. Сервер должен поддерживать `response_format: json_schema`; это проверяется реальным вызовом `smoke`. Можно указать другую открытую модель, которую обслуживает сервер. Для reasoning-моделей нужны дополнительные настройки сервера и достаточный резерв генерации; для первого теста выбран instruct-вариант без отдельного thinking-режима.

## План эксперимента

```bash
python -m context_memory fetch-benchmark --dataset personamem
python -m context_memory benchmark --dataset personamem --split eval --limit 5 --provider ollama --model qwen3:4b-instruct-2507-q4_K_M --max-api-calls 1500 --format-retries 1 --dry-run --out runs/personamem-plan
```

`--dry-run` создаёт `plan.json` без API-клиента. В нём: ID вопросов, хеши данных и промптов, модель, seed, лимиты и нижняя оценка числа вызовов. Поиск, исправления формата и дополнительное дробление могут увеличить расход. По фактически скачанным первым пяти eval-вопросам минимум составляет 580 вызовов на оба режима. Лимит 1500 ограничивает команду, но не гарантирует завершение при любых ответах модели.

Вопрос появляется после чтения. Один и тот же набор проходит оба режима, порядок между вопросами чередуется. Для отладки используйте `--split debug`; промпты после просмотра eval-ответов не меняются.

## Генерация и независимая оценка

После успешного `smoke`:

```bash
python -m context_memory benchmark --dataset personamem --split eval --limit 5 --mode both --provider ollama --model qwen3:4b-instruct-2507-q4_K_M --max-api-calls 1500 --format-retries 1 --timeout-s 180 --no-score --out runs/personamem-qwen
python -m context_memory evaluate runs/personamem-qwen --data-dir data/personamem
```

Для сервера замените провайдер и имя модели на параметры из предыдущего раздела. Полный исходный текст читается без удаления отвлекающих сообщений. Разрешён максимум один поиск на вопрос. Состояние и журнал создаются заново для каждого примера и режима.

`--no-score` сохраняет предсказания, не открывая эталоны. Команда `evaluate` читает эталоны после генерации и сохраняет отчёт в `evaluation/`; исходные результаты остаются нетронутыми. Проверяются идентичность датасета и полнота набора ответов. Модель для оценки не используется. Внутренний `verify` проверяет память агента и не является оценщиком результата.

В отчёте отдельно указаны ошибки сети, невалидные ответы, остановки по лимиту и неверные ответы, точность до и после поиска, результаты по типам вопросов, токены, вызовы и время. Неоценённые результаты имеют `accuracy: null`. Общая точность включает ошибки выполнения в знаменатель.

Дополнительная проверка BABILong:

```bash
python -m context_memory fetch-benchmark --dataset babilong
python -m context_memory benchmark --dataset babilong --limit 5 --provider ollama --model qwen3:4b-instruct-2507-q4_K_M --max-api-calls 500 --format-retries 1 --no-score --out runs/babilong-qwen
python -m context_memory evaluate runs/babilong-qwen --data-dir data/babilong
```

Для BABILong по умолчанию сохранён `question_first`; можно явно выбрать `--presentation question_later`. Результаты этих протоколов не объединяются.

## Воспроизводимость

`protocol.json` хранит параметры, хеши промптов и идентичность датасета. `predictions.jsonl` и `results.json` содержат ответы; журналы, версии памяти и `api_calls.jsonl` — исходные данные и запросы. Для локальных провайдеров фиксируется seed; точная повторяемость между разными GPU и версиями сервера не гарантируется. Usage и стоимость учитывают все записанные попытки. Записи API сохраняются после каждого вызова, в том числе перед аварийной остановкой.

Манифест можно перенести вместе с результатами: локальный путь скачанного файла не участвует в идентичности данных. Для сравнения нужны одинаковые модель, квантизация, промпты, лимиты, split и порядок предъявления вопроса. Стоимость локального API равна нулю без учёта оборудования и электричества. OpenRouter запускается только с отдельными `--live --budget-usd`; в подготовке версии 0.2 платные вызовы не выполнялись.
