## BABILong

Использован `qa1`, вариант `8k`, строки 5–9. Вопрос предъявлялся до чтения текста. Промпты перед проверкой зафиксированы; эталоны открывались только после запросов модели.

```bash
python -m context_memory fetch-benchmark --revision fc4d1a584dfc498c37578753bee4cdd91b987ae2
python -m context_memory benchmark --mode both --limit 5 --provider ollama --model llama3.2:1b --max-api-calls 500
```

Файл: `8k/qa1-00000-of-00001.parquet`, revision `fc4d1a584dfc498c37578753bee4cdd91b987ae2`, SHA-256 `aa77f2270acefcd508c067dd572678c38219fc6b1c68e74ce8f2e2a3d68227a0`. [Манифест загрузки](../examples/babilong-manifest.json).

Одинаковые лимиты обоих режимов: окно 4096, память 512, состояние 256, фрагмент до 1024, резерв ответа 768 токенов `cl100k_base`. Для всей команды разрешено до 500 попыток API; использовано 97. Окно Ollama — 8192 нативных токена.

| --- | ---: | ---: |
| Запрошено примеров | 5 | 5 |

Все завершённые ответы — `insufficient_data`. Среди нарушений схемы были повторяющиеся ID в `source_ids`. Невалидные ответы отклонены, последняя корректная память сохранена. Меньшее число вызовов `reflexive` связано с ранними остановками.

Исходные тексты содержат 7347–7588 токенов, что больше окна приложения. Аудит всех 97 запросов подтвердил соблюдение лимитов, сохранность прочитанных фрагментов и их порядок. [Аудит](validation-audit.json), [полный отчёт](../examples/local-babilong-5/report.md), [результаты JSON](../examples/local-babilong-5/results.json).
